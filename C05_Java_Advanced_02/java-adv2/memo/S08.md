# 네트워크 - 프로그램 1

## 네트워크 프로그램 1 - 예제

### 코드
```java
public class ClientV1 {

    private static final int PORT = 12345;

    public static void main(String[] args) throws IOException {
        log("클라이언트 시작");

        Socket socket = new Socket("localhost", PORT);
        // - 클라이언트는 남는 포트 중에 자동으로 포트를 할당받음
        // - localport: 할당 받은 자신 포트
        log("소켓 연결: " + socket);

        DataInputStream input = new DataInputStream(socket.getInputStream());
        DataOutputStream output = new DataOutputStream(socket.getOutputStream());

        // 서버에게 데이터 전송
        String toSend = "Hello";
        output.writeUTF(toSend); // 서버로 데이터 전달
        log("client -> server: " + toSend);

        // 서버로부터 데이터 수신
        String received = input.readUTF();
        log("client <- server: " + received);

        // 자원 정리
        log("연결 종료: " + socket);
        input.close();
        output.close();
        socket.close();
    }
}
```

```java
public class ServerV1 {

    private static final int PORT = 12345;

    public static void main(String[] args) throws IOException {
        log("서버 시작");

        ServerSocket serverSocket = new ServerSocket(PORT);
        // - 서버는 자신의 포트를 할당해주어야함
        log("서버 소켓 시작 - 리스닝 포트: " + PORT);

        Socket socket = serverSocket.accept();
        // - port: 자신과 연결된(클라이언트) 포트
        log("소켓 연결: " + socket);

        DataInputStream input = new DataInputStream(socket.getInputStream());
        DataOutputStream output = new DataOutputStream(socket.getOutputStream());

        // 클라이언트로부터 데이터 수신
        String received = input.readUTF();
        log("client -> server: " + received);

        // 클라이언트에게 데이터 송신
        String toSend = received + " World!";
        output.writeUTF(toSend);
        log("client <- server: " + toSend);

        // 자원 정리
        log("연결 종료: " + socket);
        input.close();
        output.close();
        socket.close();
        serverSocket.close();
    }
}
```

### 참고
- 클라이언트의 localport는 랜덤으로 생성되므로 매번 다른 숫자가 나올 수 있음

### localhost, 127.0.0.1
- 현재 사용 중인 컴퓨터 자체를 가리키는 특별한 호스트 이름(루프백 주소)
- 컴퓨터가 스스로를 가리킬 때 사용되며, localhost와 동일하게 취급됨
- 네트워크 인터페이스를 통해 외부로 나가지 않고, 자신에게 직접 네트워크 패킷을 보낼 수 있도록 함

### 주의 - 서버 연결 불가
- 서버를 시작하지 않고, 클라이언트만 실행하면 예외 발생
- 서버가 살아있어야지 연결을 할 수 있음

### 주의 - BindException
- 이미 할당한 포트가 내 컴퓨터의 다른 프로세스가 사용하고 있는 경우 발생할 수 있음
- 백그라운드 프로세스로 남아있는 경우, 해당 프로그램을 종료하거나 PC를 재부팅하면 됨

## 네트워크 프로그램 1 - 분석

### DNS 탐색
```java
public class InetAddressMain {

    public static void main(String[] args) throws UnknownHostException {
        InetAddress localhost = InetAddress.getByName("localhost");
        System.out.println(localhost);

        InetAddress google = InetAddress.getByName("google.com");
        System.out.println(google);
    }
}
```
- InetAddress.getByName("호스트명") 메서드를 사용해서 해당하는 IP 주소를 조회함
- 시스템의 호스트 파일을 먼저 확인
  - /etc/hosts (리눅스, mac)
  - C:\Windows\System32\drivers\etc\hosts (윈도우)
- 만약 호스트 파일에 없다면 127.0.0.1을 추가하거나 IP를 직접 사용하면 됨
- DNS 서버를 조회해서 가져옴

#### 클라이언트 코드 분석
```java
Socket socket = new Socket("localhost", PORT);
```
- localhost를 통해 자신의 컴퓨터에 있는 12345 포트에 TCP 접속을 시도(3 way handshaking)
  - 내부에서 InetAddress를 사용해서 IP 주소를 먼처 찾음
  - 127.0.0.1:12345에 TCP 접속을 시도
- 연결이 성공적으로 완료되면 Socket 객체를 반환함
- Socket은 서버와 연결되어있는 연결점이라고 생각하면 됨
- Socket 객체를 통해서 서버와 통신할 수 있음

```java
DataInputStream input = new DataInputStream(socket.getInputStream());
DataOutputStream output = new DataOutputStream(socket.getOutputStream());
```
- Socket은 서버와 데이터를 주고 받기 위한 스트림을 제공함
- InputStream: 서버에서 데이터를 클라이언트가 받을 때 사용
- OutputStream: 클라이언트에서 서버에 데이터를 전달할 때 사용
- 그냥 사용하면 모든 데이터를 byte로 변환해서 전달해야하기 때문에 번거로움
  - DataInputStream/DataOutputStream 보조 스트림을 사용해서 자바 타입의 메시지를 편리하게 주고 받을 수 있음

```java
// 서버에게 데이터 전송
String toSend = "Hello";
output.writeUTF(toSend); // 서버로 데이터 전달
log("client -> server: " + toSend);

// 서버로부터 데이터 수신
String received = input.readUTF();
log("client <- server: " + received);
```
- 스트림을 통해서 데이터 송수신

```java
// 자원 정리
log("연결 종료: " + socket);
input.close();
output.close();
socket.close();
```
- 사용한 자원은 반드시 정리해줘야함
- 생성한 역순으로 자원을 종료

### 서버 코드 분석
```java
ServerSocket serverSocket = new ServerSocket(PORT);
```
- 서버 소켓
  - 서버는 ServerSocket이라는 특별한 소켓을 사용함
  - 특정 포트를 열어두어야 함
  - 클라이언트가 해당 포트를 지정해서 접속할 수 있음

- 서버 소켓 동작 과정
  - 클라이언트에서 서버 소켓으로 연결 시도
  - OS 게층에서 TCP 3 way handshake가 발생하고 TCP 연결이 완료됨
  - TCP 연결이 완료되면 서버는 backlog queue에 연결 정보를 보관(OS backlog queue)
    - 이 연결 정보를 보면 클라이언트의 IP/PORT, 서버의 IP/PORT 정보가 모두 들어있음
  - 서버에서 클라이언트로 연결 완료를 보냄

### 클라이언트와 랜덤 포트
- TCP 연결시에는 클라이언트, 서버 모두 IP, 포트 정보가 필요함
  - 클라이언트: localhost, 포트 랜덤 생성 -
    - 코드에 적은 값: 서버의 IP/PORT (접속 대상)
    - 클라이언트 자신의 IP/PORT: OS가 자동 결정
  - 서버: localhost, 12345 / 자신의 IP/PORT를 할당 -> IP는 자동으로 할당되고, PORT는 지정

### accept()
```java
Socket socket = serverSocket.accept();
```
- **서버 소켓은 단지 클라이언트와 서버의 TCP 연결만 지원하는 특별한 소켓**
- 실제 클라이언트와 서버가 정보를 주고 받으려면 Socket 객체가 필요함 (서버 소켓 X)
- serverSocket.accept() 메서드를 호출하면 TCP 연결 정보를 기반으로 Socket 객체를 만들어서 반환함

- 호출 과정
    - accept() 호출
      - backlog queue에서 TCP 연결 정보를 조회
      - 만약 TCP 연결 정보가 없다면, 연결 정보가 생성될 때까지 대기함(**블로킹**)
    - 해당 정보를 기반으로 Socket 객체를 생성
    - 사용한 TCP 연결 정보는 backlog queue에서 제거됨

- 이후에는 소켓의 스트림으로 통신을 진행하고 
- 자원을 해제함(주의: **서버 소켓도 정리해야함**)

## 네트워크 프로그램 2 - 예제

### 코드
```java
public class ClientV2 {

    private static final int PORT = 12345;

    public static void main(String[] args) throws IOException {
        log("클라이언트 시작");

        Socket socket = new Socket("localhost", PORT);
        // - 클라이언트는 남는 포트 중에 자동으로 포트를 할당받음
        // - localport: 할당 받은 자신 포트
        log("소켓 연결: " + socket);

        DataInputStream input = new DataInputStream(socket.getInputStream());
        DataOutputStream output = new DataOutputStream(socket.getOutputStream());

        Scanner scanner = new Scanner(System.in);
        while (true) {
            System.out.print("전송 문자: ");
            String toSend = scanner.nextLine();

            // 서버에게 데이터 전송
            output.writeUTF(toSend); // 서버로 데이터 전달
            log("client -> server: " + toSend);

            if (toSend.endsWith("exit")) {
                break;
            }

            // 서버로부터 데이터 수신
            String received = input.readUTF();
            log("client <- server: " + received);
        }

        // 자원 정리
        log("연결 종료: " + socket);
        input.close();
        output.close();
        socket.close();
    }
}
```

## 네트워크 프로그램 2 - 분석

### 서버 소켓과 연결 더 자세히
- 여러 클라이언트가 서버에 접속한다고 가정
  - 서버는 12345 서버 소켓을 열어둠
  - 500000번 랜덤 포트를 사용하는 클라이언트가 먼저 12345 포트의 서버에 접속을 시도
  - OS 게층에서 TCP 3 way handshake가 발생하고, TCP 연결이 완료됨
  - TCP 연결이 완료되면 서버는 OS backlog queue라는 곳에 클라이언트와 서버의 TCP 연결 정보르 보관

- 여기서 중요한 점
  - 이 시점에 TCP 3 way handshake가 완료되었기 때문에, 클라이언트와 서버의 TCP 연결은 이미 완료되고, 
  - 클라이언트의 소켓 객체도 정상 생성

- 이번에는 60000번 랜덤 포트를 사용하는 클라이언트가 12345 포트의 서버에 접속을 시도하고 연결이 완료
- 50000번 / 60000번 클라이언트 모두 서버와 연결이 완료되었고, 클라이언트의 소켓도 정상 생성됨

- **연결은 완료되어서 메세지를 보낼 수 있음을 생각하자!!!**

### 클라이언트가 "Hello World"라는 메시지를 서버에 전송하는 경우
- 클라이언트
  - 애플리케이션 -> OS TCP 송신 버퍼 -> 클라이언트 네트워크 카드
- 클라이언트가 보낸 메시지가 서버에 도착했을 때 서버
  - 서버 네트워크 카드 -> OS TCP 수신 버퍼 -> 애플리케이션

- 여기서 60000번 클라이언트가 보낸 메시지는 서버 애플리케이션에서 아직 읽지 않았기 때문에,
- 서버 OS의 TCP 수신 버퍼에서 대기하게 됨

### 핵심
- 소켓 객체 없이 서버 소켓만으로도 TCP 연결은 완료된다는 점
- **하지만 연결 이후에 서로 메시지를 주고 받으려면 소켓 객체가 필요함**
- accept()는 이미 연결된 TCP 연결 정보를 기반으로 서버 측에 소켓 객체를 생성함
- 그리고 이 소켓 객체가 있어야 스트림을 사용해서 통신할 수 있음

### 참고
- accept() 메서드는 backlog 큐에 새로운 연결 정보가 도착할 때까지 블로킹 상태로 대기함
- **새로운 연결 정보가 오지 않으면 계속 대기하는 블로킹 메서드**

### 그래서 문제가 발생하는 이유
```java
Socket socket = serverSocket.accept();
// - port: 자신과 연결된(클라이언트) 포트
log("소켓 연결: " + socket);

DataInputStream input = new DataInputStream(socket.getInputStream());
DataOutputStream output = new DataOutputStream(socket.getOutputStream());

while (true) {
    // 클라이언트로부터 데이터 수신
    String received = input.readUTF();
    log("client -> server: " + received);

    if (received.equals("exit")) {
        break;
    }

    // 클라이언트에게 데이터 송신
    String toSend = received + " World!";
    output.writeUTF(toSend);
    log("client <- server: " + toSend);
}
```
- while 문 밖에서 accept()를 호출하고 있어서 소켓 객체를 생성할 수 없는 상황

### ServerV2의 문제
- 새로운 클라이언트가 접속하면?
  - 새로운 클라이언트가 접속했을 때 서버의 main 스레드는 accept() 메서드르 절대로 호출할 수 없음
  - while 문으로 기존 클라이언트와 메시지를 주고 받는 부분만 반복하기 때문
  - accept()를 호출해야 소켓 객체를 생성하고 클라이언트와 메시지를 주고 받을 수 있음

- 2개의 블로킹 작업 - 핵심은 별도의 스레드가 필요함
  - accept(): 클라이언트와 서버의 연결을 처리하기 위해 대기
  - readXxx(): 클라이언트와 메시지를 받아서 처리하기 위해 대기
  - 각각의 블로킹 작업은 별도의 스레드에서 처리해야함. 그렇지 않으면 다른 블로킹 메서드 때문에 계속 대기할 수 있음

## 네트워크 프로그램 3

### 목적
- 여러 클라이언트가 동시에 접속할 수 있는 서버 프로그램

### 방법
- 서버의 main 스레드는 서버 소켓을 생성하고, 서버 소켓의 accept()를 반복해서 호출해야함
- 클라이언트가 서버에 접속하면 서버 소켓의 accept() 메서드가 Socket을 반환함
- main 스레드는 이 정보를 기반으로 Runnable을 구현 Session이라는 별도의 객체를 만들고, 새로운 스레드에서 이 객체를 실행함
- Session 객체와 Thread-0은 연결된 클라이언트와 메시지를 주고 받음

### 역할의 분리
- main 스레드
  - main 스레드는 새로운 연결이 있을 때마다 Session 객체와 별도의 스레드를 생성하고, 별도의 스레드가 Session 객체를 실행하도록 함
- Session 담당 스레드
  - Session을 담당하는 스레드는 자신의 소켓이 연결된 클라이언트와 메시지를 반복해서 주고 받는 역할을 담당함

### 코드
```java
public class ServerV3 {

    private static final int PORT = 12345;

    public static void main(String[] args) throws IOException {
        log("서버 시작");

        ServerSocket serverSocket = new ServerSocket(PORT);
        log("서버 소켓 시작 - 리스닝 포트: " + PORT);

        while (true) {
            Socket socket = serverSocket.accept(); // 블로킹
            log("소켓 연결: " + socket);

            Thread session = new Thread(new SessionV3(socket));
            session.start();
        }
    }
}
```

```java
public class SessionV3 implements Runnable {

    private final Socket socket;

    public SessionV3(Socket socket) {
        this.socket = socket;
    }

    @Override
    public void run() {
        try {
            DataInputStream input = new DataInputStream(socket.getInputStream());
            DataOutputStream output = new DataOutputStream(socket.getOutputStream());

            while (true) {
                // 클라이언트로부터 문자 받기
                String received = input.readUTF();
                log("client -> server: " + received);

                if (received.equals("exit")) {
                    break;
                }

                // 클라이언트에게 문자 보내기
                String toSend = received + " World!";
                output.writeUTF(toSend);
                log("client <- server: " + toSend);
            }

            log("연결 종료: " + socket);
            input.close();
            output.close();
            socket.close();
        } catch (IOException e) {
            throw new RuntimeException(e);
        }
    }
}
```

### 아쉬운 점
- 클라이언트를 직접 종료한 경우 서버 로그
- 클라이언트의 연결을 직접 종료하면 클라이언트 프로세스가 종료되면서, 클라이언트와 서버의 TCP 연결도 함께 종료됨
- 이때 서버에서 readUTF()로 클라이언트가 메시지를 읽으려고 하면 EOFException이 발생함
- 소켓의 TCP 연결이 종료되었기 때문에 더는 읽을 수 있는 메시지가 없다는 뜻
- EOF -> 전송의 끝
- 심각한 문제
  - 예외가 발생하면 서버에서 자원 정리 코드를 호출하지 못함
  - 서버 로그를 보면 연결 종료 로그가 없는 것을 확인할 수 있음
  - 자바 객체는 GC가 되지만 자바 외부의 자원은 자동으로 GC가 되는 것이 아님
  - 따라서 꼭! 정리를 해주어야함
  - **자원 정리는 매우 매우 중요하다!!!**

## 자원 정리 2

### 예제 코드
- 예외가 발생해도 자원을 정리할 수 있게 하는 것이 목적
```java
public class ResourceCloseMainV2 {

    public static void main(String[] args) {
        try {
            logic();
        } catch (CallException e) {
            System.out.println("CallException 예외 처리");
            throw new RuntimeException(e);
        } catch (CloseException e) {
            System.out.println("CloseException 에외 처리");
            throw new RuntimeException(e);
        }
    }

    private static void logic() throws CallException, CloseException {

        ResourceV1 resource1 = null;
        ResourceV1 resource2 = null;

        try {
            resource1 = new ResourceV1("resource1"); // 만약 여기서 예외가 터진다면
            resource2 = new ResourceV1("resource2"); // 2번은 null인 상태로 finally로 가서 문제가 발생할 수 있음

            resource1.call();
            resource1.callEx(); // CallException
        } catch (CallException e) {
            System.out.println("ex: " + e);
            throw e;
        } finally {
            System.out.println("자원 정리"); // 호출 됨

            if (resource2 != null) {
                resource2.closeEx(); // 자원 정리 중 예외 발생
                // - CallException이 던져지는게 아니라 CloseException이 던져짐
            }

            if (resource1 != null) {
                resource1.closeEx(); // 호출 안됨
            }
        }
    }
}
```

### null 체크
- 생성 중에 예외가 발생할 수도 있기 때문에 생성되지 않은 자원에 대해서 정리를 진행할 수 없음
- null 체크가 필요함

### 자원 정리 중에 예외가 발생하는 문제
- 자원을 정리하는 중에도 문제가 발생할 수 있음
- rs1을 닫지 못하는 문제가 발생

### 핵심 예외가 바뀌는 문제
- 본질적인 예외는 CallException
- 근데 finally를 호출하는 중에 CloseException이 터지면서 CallEx대신 CloseEx가 던져짐
- 핵심 예외가 사라져서 제대로 된 문제를 찾을 수 없음

### 정리
- close() 시점에 실수로 예외를 던지면, 이후 다른 자원을 닫을 수 없는 문제 발생
- finally 블럭 안에서 자원을 닫을 때 예외가 발생하면, 핵심 예외가 finally에서 발생한 부가 예외로 바뀌어 버리고 핵심 예외가 사라짐

## 자원 정리 4

### try-with-resources
```java
public class ResourceCloseMainV4 {

    public static void main(String[] args) {
        try {
            logic();
        } catch (CallException e) {
            System.out.println("CallException 예외 처리");

            Throwable[] suppressed = e.getSuppressed();
            for (Throwable throwable : suppressed) {
              System.out.println("suppressedEx = " + throwable);
            }
            
            throw new RuntimeException(e);
        } catch (CloseException e) {
            System.out.println("CloseException 에외 처리");
            throw new RuntimeException(e);
        }
    }

    private static void logic() throws CallException, CloseException {
        try (
                ResourceV2 resource1 = new ResourceV2("resource1");
                ResourceV2 resource2 = new ResourceV2("resource2");
        ) {
            resource1.call();
            resource2.callEx();
        } catch (CallException e) {
            System.out.println("ex: " + e);
            throw e;
        }
    }
}
```

```text
resource1 call
resource2 callEx
resource2 close
resource1 close
ex: network.tcp.autocloseable.CallException: resource2 ex
CallException 예외 처리
```
- resource2가 먼저 닫아짐(나중에 선언한 걸 먼저 닫아줌)

### try-with-resources에서 자원을 닫는 중 예외가 발생할 경우
- 핵심 예외가 던져짐
```java
Throwable[] suppressed = e.getSuppressed();
for (Throwable throwable : suppressed) {
    System.out.println("suppressedEx = " + throwable);
}
```
- 자원을 닫는 중 발생한 예외를 핵심 예외 안에 넣어줌

### 2가지 핵심 문제 해결
- close() 시점에 실수로 예외를 던지면 이후 다른 자원을 닫을 수 없는 문제 발생
- finally 블럭 안에서 자원을 닫을 때 예외가 발생하면, 핵심 예외가 finally에서 발생한 부가 예외로 바뀌어버리는 문제 + 핵심 예외가 사라지는 문제

### 4가지 부가 문제 해결
- resource 변수를 선언하면서 동시에 할당할 수 없음(try-finally 스코프 문제)
- catch 이후에 finally 호출/자원 정리가 조금 늦어지는 문제
  - try-with-resources는 예외가 발생하면 자원 정리를 먼저한 이후에 catch를 실행함
- 개발자가 실수로 close()를 호출하지 않을 가능성
- 개발자가 close() 순서를 실수할 가능성
  - 선언한 순서 역순으로 닫아줌

### 장점
- 리소스 누수 방지
- 코드 간결성 및 가독성 향상
- 스코프 범위 한정
- 조금 더 빠른 자원 해제
- 자원 정리 순서
- 부가 예외 포함

### 부가 예외 포함
- try-with-resources는 핵심 예외를 반환함
- 부가 예외는 핵심 예외 안에 Suppressed로 담아서 반환
- 개발자는 자원 정리 중에 발생한 부가 예외를 e.getSupressed()를 통해 활용할 수 있음
- 참고:
  - e.addSuppressed(ex)라는 메서드가 있어서 예외 안에서 참고할 예외를 담아둘 수 있음
  - 이 기능도 try-with-resources가 등장하면서 같이 만들어짐
