# 네트워크 - 기본 이론

## 클라이언트와 서버

### 클라이언트-서버 개념의 기본 이해
- 클라이언트: 클라이언트는 서비스를 요청하는 쪽
  - 식당에서 음식을 주문하는 손님
  - 어떤 정보를 얻거나 작업을 처리해달라고 요청하는 역할을 함

- 서버: 서버는 클라이언트의 요청을 받아들이고, 그 요청에 맞게 서비스를 제공하는 쪽
  
### 객체와 클라이언트-서버 관게
- Main 클래스 -> Service 클래스의 메서드 호출(요청)
    - Main 클래스: 클라이언트
    - Service 클래스: 서버
    - **반환 타입이 void여도 서버라고 할 수 있음**

### 네트워크와 클라이언트-서버
- 요청을 보내는 장치가 클라이언트
- 요청을 받고 응답을 내려주는 장치가 서버

### 클라이언트와 서버가 동시에 될 수도 있음
- 서버가 다른 서버에게 요청을 보냄(클라이언트이자 서버)

### 정리
- 클라이언트 - 서버는 특별한 것이 아님
- 요청을 보내는 쪽 클라이언트
- 요청을 받고 처리하는 쪽 서버
- 네트워크에만 한정된게 아님!

## IP(Internet Protocol)

### 인터넷 프로토콜 역할
- 지정한 IP 주소(IP Address)에 데이터 전달
- 패킷이라는 통신 단위로 데이터 전달

### IP 패킷 정보
- 출발지 IP / 목적지 IP / 기타 정보를 담은 패킷을 생성
- 노드가 이 정보를 바탕으로 인터넷에 있는 수많은 노드들은 통해서 목적지에 도착함

### IP 프로토콜의 한계
- 비연결성
  - 패킷을 받을 대상이 없거나 서비스 불능 상태여도 패킷 전송

- 비신뢰성
  - 중간에 패킷이 사라지면?
  - 패킷이 순서대로 안오면?

- 프로그램 구분
  - 같은 IP를 사용하는 서버에서 통신하는 애플리케이션이 둘 이상이면?

### 대상이 서비스 불능, 패킷 전송
- 대상 서버가 패킷을 받을 수 있는 상태인지 모름

### 패킷 소실
- 중간 인터넷 노드 중 하나가 문제가 되면 패킷을 전송할 수 없음

### 패킷 전달 순서 문제 발생
- 각 패킷이 노드를 타서 전달하는 순서가 다를 수도 있음

### 위 문제를 해결
- TCP
- UDP(이걸 해결한다기보다는 도움이 되는게 있음)

## TCP/UDP

### 인터넷 프로토콜 스택의 4계층
- 애플리케이션 계층 - HTTP, FTP
- 전송 계층 - TCP, UDP
- 네트워크 계층 - IP
- 네트워크 인터페이스 계층

### 프로토콜 계층
- 애플리케이션(크롬, 게임, SOCKET 라이브러리)
- OS(TCP, IP)
- 네트워크 인터페이스(LAN 드라이버, LAN 장비)

### 패킷 생성 과정 약식
- 애플리케이션: 프로그램이 Hello, World! 메시지 생성
- 애플리케이션: 소켓 라이브러리를 통해 전달
- OS: TCP 정보 생성, 메시지 데이터 포함
- OS: IP 패킷 생성, TCP 데이터 포함
- 네트워크 인터페이스: LAN 카드로 패킷이 나감

### IP 패킷 정보
- 출발지 IP, 목적지 IP, 기타...

### TCP/IP 패킷 정보
- 출발지 PORT, 목적지 PORT
- **전송 제어, 순서, 검증 정보, ...**

### TCP 특징
- 전송 제어 프로토콜(Transmission Control Protocol)
  - 연결 지향 - TCP 3 way handshake (가상 연결)
  - 데이터 전달 보증
  - 순서 보장

- 신뢰할 수 있는 프로토콜
- 현재는 대부분 TCP 사용

### 연결 지향 - TCP 3 way handshake
- 클라이언트 -> 서버
  - SYN

- 서버 -> 클라이언트
  - SYN + ACK

- 클라이너트
  - ACK

- SYN: 접속 요청
- ACK: 요청 수락
- 참고: 3. ACK와 함께 데이터 전송 가능(최적화)

- **주의**
  - 진짜로 연결되었다가 아님
  - 가상으로 연결되었음을 말하는 것임

### 데이터 전달 보증
- 데이터를 전송하면
- 데이터를 잘 받았다고 응답을 해줌

### 순서 보장
- 패킷 순서를 맞춰야할 경우, 어디서부터 다시 보낼 수 있게 다시 요청함
- 물론 내부적으로 가지고 있다 재조립해도 됨(최적화 영역)

### UDP 특징
- 사용자 데이터그램 프로토콜(User Datagram Protocol)
  - 기능이 거의 없음
  - 연결지향 X
  - 데이터 전달 보증 X
  - 순서 보장 X
  - **데이터 전달 및 순서가 보장되지 않지만, 단순하고 빠름**

- 정리
  - IP와 거의 같음
  - **PORT + 체크섬**정도만 추가
  - 애플리케이션에서 추가 작업 필요

## PORT

### 한 번에 둘 이상 연결하려면?
- TCP/IP 패킷에 출발지 PORT/목적지 PORT가 있음

### 그래서 PORT란
- **같은 IP 내에서 프로세스 구분**
- 게임 서버 연결 포트: 20001번 포트
- 웹 브라우저 요청 포트: 20132번 포트

### PORT
- 0 ~ 65535 할당 가능(2바이트)
- 0 ~ 1023: 잘 알려진 포트, 사용하지 않는 것이 좋음
  - FTP - 20, 21
  - TELNET - 23
  - HTTP - 80
  - HTTPS - 443

## DNS

### IP는 변경될 수 있음
- IP가 변경되면 다시 IP를 알아야하는 번거로움이 있음

### DNS
- 도메인 네임 시스템(Domain Name System)
  - 전화번호 부
  - 도메인 명을 IP 주소로 변환

### DNS 사용
1. 도메인 명 google.com -> DNS 서버
2. DNS 서버에서 IP를 찾아서 반환해줌(물론 IP를 컴퓨터 내부적으로 가지고 있는 경우도 있음)
3. 해당 IP로 접속
