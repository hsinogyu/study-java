# I/O 기본 1

## 스트림 시작 1

### new FileOutputStream("temp/hello.dat")
- 파일에 데이터를 출력하는 스트림
- 파일이 없으면 파일을 자동으로 만들고, 데이터를 해당 파일에 저장함
- 폴더를 만들지는 않기 때문에 폴더를 미리 만들어두어야함

### write()
- byte 단위로 값을 출력함
- 참고로 ASCII 코드 집합에서 65는 A, 66은 B, 67은 C

### new FileInputStream("temp/hello.dat")
- 파일에서 데이터를 읽어오는 스트림

### read()
- 파일에서 데이터를 byte 단위로 하나씩 읽어옴
- 순서대로 65, 66, 67을 읽어옴
- 파일의 끝에 도달해서 더는 읽을 내용이 없다면 -1을 반환함
  - 파일의 끝(EOF, End of File)

### close()
- 파일에 접근하는 것은 자바 입장에서 외부 자원을 사용하는 것
- 자바에서 내부 객체는 자동으로 GC가 되지만 외부 자원은 사용 후에 반드시 닫아주어야함

### 참고: 파일 append 옵션
```java
new FileOutputStream("temp/hello.dat", true);
```
- true: 기존 문서가 있다면 기존 문서의 끝에 출력함
- false(default): 기존 문서가 있어도 지우고 다시 출력함

### 참고: read()가 int를 반환하는 이유
- read()는 바이트 기반으로 읽는데 왜 int로 반환을 하는 것일까?
  - 부호 없는 바이트 표현
    - 자바에서 byte는 부호 있는 8비트 값(-128 ~ 127)
    - int로 반환함으로써 0에서 255까지의 모든 가능한 바이트 값을 부호 없이 표현할 수 있음
  - EOF 표시
    - byte를 표현하려면 256 종류의 값을 모두 사용해야함
    - 자바의 byte는 -128 ~ 127까지 256종류의 값만 가질 수 있어, EOF를 위한 특별한 값을 할당하기 어려움
    - int는 0 ~ 255까지 모든 가능한 바이트 값을 표현하고, 여기에 추가로 -1을 반환하여 스트림의 끝을 나타낼 수 있음
  - 참고로 write()의 경우도 비슷한 이유로 int 타입을 입력 받음

## 스트림 시작 2

### write(byte[])
- byte[]에 원하는 데이터를 담고 write()에 전달하면 해당 데이터를 한 번에 출력할 수 있음

### read(byte[], int offset, int length)
- byte[]를 미리 만들어두고, 만들어둔 byte[]에 한 번에 데이터를 읽어올 수 있음
- byte[]: 데이터가 읽혀지는 버퍼
- offset: 데이터가 기록되는 byte[]의 인덱스 시작 위치
- length: 읽어올 byte의 최대 길이
- 반환 값: 버퍼에 읽은 총 바이트 수 여기서는 3byte를 읽었으므로 3이 반환됨
    - 더 이상 데이터가 없는 경우 -1을 반환

### 부분으로 나누어 읽기 vs 전체 읽기
- read(byte[], offset, length)
  - 스트림의 내용을 부분적으로 읽거나, 읽은 내용을 처리하면서 스트림을 계속해서 읽어야 할 경우에 적합함
  - 메모리 사용량을 제어할 수 있음
  - 대용량 파일을 처리할 때, 한 번에 메모리에 로드하기보다는 이 메서드를 사용하여 파일을 조각조각 읽어들일 수 있음
- readAllBytes()
  - 한 번의 호출로 모든 데이터를 읽을 수 있어 편리함
  - 작은 파일이나 메모리에 모든 내용을 올려서 처리해야 하는 경우에 적합함
  - 메모리 사용량을 제어할 수 없음
  - 큰 파일의 경우 OutOfMemoryError가 발생할 수 있음

## InputStream, OutputStream

### InputStream
- read() / read(byte[]) / readAllBytes()
  - FileInputStream
  - ByteArrayInputStream
  - SocketInputStream

### OutputStream
- write(int) / write(byte[])
  - FileOutputStream
  - ByteArrayOutputStream
  - SocketOutputStream

### 메모리 스트림
- ByteArrayOutputStream / ByteArrayInputStream을 사용하면 메모리에 스트림을 읽고 쓸 수 있음
- 참고로 메모리에 어떤 데이터를 저장하고 읽을 때는 컬렉션이나 배열을 사용하면 되기 때문에 잘 사용하지 않음

### 콘솔 스트림
- PrintStream(OutputStream을 상속 받음)
- write(byte[]): OutputStream 부모 클래스가 제공하는 기능
- println(String): PrintStream이 자체적으로 제공하는 추가 기능

## 파일 입출력과 성능 최적화 1 - 하나씩 쓰기

### 1바이트 씩 10MB 파일을 읽는 경우
- 약 1000만 번의 write() / read()가 호출됨
- 성능이 느려지는 조금 더 정확한 이유
  - write() / read()를 호출할 때마다 OS의 시스템 콜을 통해 파일을 읽거나 쓰는 명령어를 전달함
  - 시스템 콜은 상대적으로 무거운 작업
  - HDD / SDD 같은 장치들도 하나의 데이터를 읽고 쓸 때마다 필요한 시간이 있음
  - HDD의 경우 더 느린데, 물리적으로 디스크의 회전이 필요함

### 참고
- 자바에서 운영체젲를 통해 디스크에 1byte씩 전달하면, 운영체제나 하드웨어 레벨에서 여러가지 최적화가 발생함
- 따라서 실제로 디스크에 1byte식 계속 쓰는 것은 아님
- 그래도 결국 자주 발생하는 시스템 콜로 인한 성능 저하는 피할 수 없음

## 파일 입출력과 성능 최적화 2 - 버퍼 활용

### 버퍼로 쓰기
```java
public class CreateFileV2 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fis = new FileOutputStream(BufferedConst.FILE_NAME);

        long startTime = System.currentTimeMillis();

        byte[] buffer = new byte[BufferedConst.BUFFER_SIZE];
        int bufferIndex = 0;
        for (int i = 0; i < BufferedConst.FILE_SIZE; i++) {
            buffer[bufferIndex++] = 1;

            // 버퍼가 가득차면 쓰고, 버퍼를 비움
            if (bufferIndex == BufferedConst.BUFFER_SIZE) {
                fis.write(buffer);
                bufferIndex = 0;
            }
        }

        // 끝 부분에 오면 버퍼가 가득차지 않고, 남아있을 수 있음. 버퍼에 남은 부분 쓰기
        if (bufferIndex > 0) {
            fis.write(buffer, 0, bufferIndex);
        }

        fis.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File created: " + BufferedConst.FILE_NAME);
        System.out.println("File size: " + BufferedConst.FILE_SIZE / 1024 / 1024 + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 버퍼의 사이즈에 따른 성능 차이
- **버퍼의 사이즈가 커진다고 선형적으로 성능이 빨라지는 것이 절대 아님**
- 디스크나 파일 시스템에서 데이터를 읽고 쓰는 기본 단위가 보통 4KB 또는 8KB이기 때문임
- 따라서 버퍼에 많은 데이터를 담아서 보내도 효율에 한계가 있음

### 버퍼로 읽기
```java
public class ReadFileV2 {

    public static void main(String[] args) throws IOException {
        FileInputStream fis = new FileInputStream(BufferedConst.FILE_NAME);

        long startTime = System.currentTimeMillis();

        byte[] buffer = new byte[BufferedConst.BUFFER_SIZE];
        int fileSize = 0;
        int readCount = 0;

        while ((readCount = fis.read(buffer, 0, BufferedConst.BUFFER_SIZE)) != -1) {
            fileSize += readCount;
        }

        fis.close();

        long endTime = System.currentTimeMillis();

        System.out.println("File name: " + BufferedConst.FILE_NAME);
        System.out.println("File size: " + fileSize / 1024 / 1024 + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

## 파일 입출력과 성능 최적화 3 - Buffered  스트림 쓰기

### BufferedOutputStream
- 버퍼 기능을 내부에서 대신 처리해줌
- 단순한 코드를 유지하면서 버퍼를 사용하는 이점도 함께 누릴 수 있음
```java
public class CreateFileV3 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream(BufferedConst.FILE_NAME);
        BufferedOutputStream bos = new BufferedOutputStream(fos, BufferedConst.BUFFER_SIZE);

        long startTime = System.currentTimeMillis();

        for (int i = 0 ; i < BufferedConst.FILE_SIZE; i++) {
            bos.write(1); // 약 1000만 번 호출
        }

        bos.close();

        long endTime = System.currentTimeMillis();

        System.out.println("File created: " + BufferedConst.FILE_NAME);
        System.out.println("File size: " + BufferedConst.FILE_SIZE / 1024 / 1024 + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```
- BufferedOutputStream은 내부에서 단순히 버퍼 기능만 제공함
- 따라서 반드시 대상 OutputStream이 있어야함
- 여기서는 FileOutputStream 객체를 생성자에 전달함
- 추가로 사용할 버퍼의 크기도 함게 전달할 수 있음
- 코드를 보면 버퍼를 위한 byte[]를 직접 다루지 않고, 마치 에제 1과 같이 단순하게 코드를 작성할 수 있음

### 버퍼 작동 원리
- 내부적으로 버퍼가 다 차면 flush()를 호출함
- close()를 호출하면 버퍼에 데이터가 남아있을 수 있으므로 flush() 호출하고 close()를 호출함
- close()가 될 때, 생성자로 넘겼던 OutputStream의 close()를 호출함

### close() 시 주의사항
- **반드시 마지막에 연결한 스트림을 닫아야 함**
- BufferedOutputStream를 닫지 않으므로 버퍼에 데이터가 있었어도 flush()를 호출하지 않음
- 마지막에 연결한 스트림만 닫아주면 연쇄적으로 close()가 호출됨

### 기본 스트림 / 보조 스트림
- FileOutputStream과 같이 단독으로 사용할 수 있는 스트림을 기본 스트림이라고 함
- BufferedOutputStream과 같이 단독으로 사용할 수 없고, 보조 기능을 제공하는 스트림을 보조 스트림이라고 함

## 파일 입출력과 성능 최적화 4 - Buffered 스트림 읽기

### BufferedInputStream
```java
public class ReadFileV3 {

    public static void main(String[] args) throws IOException {
        FileInputStream fis = new FileInputStream(BufferedConst.FILE_NAME);
        BufferedInputStream bis = new BufferedInputStream(fis, BufferedConst.BUFFER_SIZE);

        long startTime = System.currentTimeMillis();

        int fileSize = 0;
        int data = 0;
        while ((data = bis.read()) != -1) { // 약 1000만 번 호출
            fileSize++;
        }
        bis.close();

        long endTime = System.currentTimeMillis();

        System.out.println("File name: " + BufferedConst.FILE_NAME);
        System.out.println("File size: " + fileSize / 1024 / 1024 + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 버퍼 작동 원리
- read()를 호출하면
- FileInputStream에서 read(byte[])로 BufferedInpuStream에서 데이터를 가져오고
- 클라이언트한테는 1byte를 반환함
- 버퍼가 빌 때까지 반복
- 버퍼가 비면 다시 버퍼의 크기만큼 read(byte[])를 호출함

### 버퍼를 직접 다루는 것보다 BufferedXxx의 성능이 떨어지는 이유
- **동기화**
- BufferedXxx 클래스는 자바 초창기에 만들어진 클래스인데, 처음부터 멀티 스레드를 고려해서 만든 클래스
- 멀티 스레드에 안전하지만 락을 걸고 푸는 동기화 코드로 인해 성능이 약간 저하될 수 있음
- 그래도 성능상 어느정도 빠름
- 성능을 극한으로 최적화해야 할 경우에는 직접 버퍼를 만들어서 사용해도 됨

## 파일 입출력과 성능 최적화 5 - 한 번에 쓰기

### 한 번에 쓰기
```java
public class CreateFileV4 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream(BufferedConst.FILE_NAME);

        long startTime = System.currentTimeMillis();

        byte[] buffer = new byte[BufferedConst.FILE_SIZE];
        for (int i = 0 ; i < BufferedConst.FILE_SIZE; i++) {
            buffer[i] = 1;
        }
        fos.write(buffer);

        fos.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File created: " + BufferedConst.FILE_NAME);
        System.out.println("File size: " + BufferedConst.FILE_SIZE / 1024 / 1024 + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 한 번에 읽기
```java
public class ReadFileV4 {

    public static void main(String[] args) throws IOException {
        FileInputStream fis = new FileInputStream(BufferedConst.FILE_NAME);

        long startTime = System.currentTimeMillis();

        byte[] buffer = fis.readAllBytes();

        int fileSize = buffer.length;
        
        fis.close();

        long endTime = System.currentTimeMillis();

        System.out.println("File name: " + BufferedConst.FILE_NAME);
        System.out.println("File size: " + fileSize / 1024 / 1024 + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### readAllBytes()
- 자바 구현에 따라 다르지만 보통 4, 8, 16KB 단위로 읽어들임

## 정리

### 정리
- 파일의 크기가 크지 않아서, 메모리 사용에 큰 영향을 주지 않는다면 쉽고 빠르게 한 번에 처리하자
- 성능이 중요하고 큰 파일을 나누어 처리해야 한다면, 버퍼를 직접 다루자
- 성능이 크게 중요하지 않고, 버퍼 기능이 필요하면 BufferedXxx를 사용하자
  - BufferedXxx는 동기화 코드가 들어있어서 멀티 스레드에 안전하지만, 약간의 성능 저하가 있음
